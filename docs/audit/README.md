# School platform page-by-page audit

## Audit inventory (11 November 2026)

- `route_inventory.csv`: 1,359 Django route declarations, with named-route reversal and the bound view where available.
- `template_inventory.csv`: 481 Django HTML templates with per-file static flags.
- `page_response_matrix.csv`: generated by the isolated `apps.core.test_page_audit` test once its database migration and request run finish.

All 481 templates compiled successfully during this audit. Django `manage.py check` passed with four existing django-allauth deprecation warnings.

### Static findings requiring review

| Rule | Templates flagged | Interpretation |
| --- | ---: | --- |
| `PLACEHOLDER_ANCHOR` | 115 | `href="#"` may be a dead navigation item or a legitimate JS trigger. Inspect and repair individually. |
| `DISABLED_BUTTON` | 47 | May be a nonfunctional feature, role restriction, or intentionally disabled submit state. Verify behavior. |
| `INLINE_CLICK_HANDLER` | 182 | Not automatically broken, but is harder to test and may rely on missing JavaScript. |

The analyzer is **read-only** and does not imply every flagged instance is defective. It does not execute JavaScript, authenticate all roles, submit forms, verify object-specific URLs, or validate database mutations. A template compiling does not prove its corresponding view works.

### Runtime test approach

`apps.core.test_page_audit.PageResponseAudit` exercises guest and superuser GET responses on all argument-free routes other than action-like routes. It runs against Django's disposable test database, not live PythonAnywhere data, and writes a response matrix. A 200, 302, 403, or 405 result can be expected depending on access and method; 500s and exceptions are failures requiring investigation. Dynamic paths requiring UUID or integer objects are not covered by that matrix and need fixtures for each object type.

### Priority follow-up

1. Resolve any runtime 500s and broken redirects before publishing UI changes.
2. Audit the public login, admissions, password reset, and guest routes with realistic form submissions.
3. Audit administrator workflows for institutions, users, academic sessions, classes, enrollment, subjects, attendance, assessment, finance, and reports.
4. Repeat role-specific journeys for teachers, students, parents, and staff with authorization boundaries.
5. Verify responsive/mobile layouts, accessibility, and actual JS behaviors in a browser.
6. Remove dead controls only after confirming they are not intentional UI state.

This is an audit inventory and test harness; **it is not a certification that every page and business rule is correct**.
